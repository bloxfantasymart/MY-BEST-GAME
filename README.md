# Roll a Brainrot — playable development build

This repository contains an **unfinished Roblox game**: a generated six-plot world, server-owned rolling and crafting, stands and income, mutations, leveling, rebirths, UTC-synchronized events, daily quests, timed session gifts and rewards, a guided tutorial, plot themes and titles, an ascension forge, capped offline earnings, animated placeholder displays and a first persistence implementation. The separate hub currently supports showcases only; item trading, developer products and many polish features are not yet implemented. Optional gamepass hooks exist but are disabled until configured. See [the roadmap](docs/ROADMAP.md).

**Please test this in a private test experience first.** It has not been run in Roblox Studio in this environment. Do not sell paid items or advertise it as complete. We cannot guarantee saving or prevent data loss until Studio and live multiplayer tests have passed.

## Setup for beginners

1. Install [Roblox Studio](https://create.roblox.com/) and sign in. Create a new **Baseplate** experience.
2. Install [Rojo 7.7](https://rojo.space/docs/v7/getting-started/installation/) on your computer and install the Rojo Studio plugin. Download this repository from GitHub using **Code → Download ZIP** and extract it. Make sure you download the branch `arena/323aed2b-my-best-game`, not `main`.
3. Open a terminal in the extracted folder (containing `default.project.json`) and run `rojo serve`.
4. In Studio, open **Plugins → Rojo** and connect (normally `localhost:34872`). Keep Rojo running while editing. The scripts sync into the Roblox services automatically.
5. Press **Play**. At your red station, use the prompt, press **PULL LEVER**, and buy parts. Reroll for a Head, Chest, Arms and Legs. At the purple pod, select one of each, review the preview and confirm assembly. Use a yellow stand's prompt to place your creature. Click the cash HUD or use the green ATM to collect income. Use **UPGRADES** for roll slots and extra stands. In **BACKPACK**, tap a creature to choose whether to level or sell it; parts can be sold there too. Use **REBIRTH** to see its requirements, and **TRAVEL** to get around your plot.
6. For multiplayer testing, publish via **File → Publish to Roblox**, then set maximum players to **6** in Creator Dashboard. Use Studio's **Test → Server & Clients** too. You must configure the player limit yourself.

Alternative: `rojo build default.project.json -o RollABrainrot.rbxlx` creates a place file you can open in Studio. Do not move scripts into different folders.

### More gameplay controls

- **Tutorial:** follow the goal at the top left and the highlighted station. Complete all six server-verified steps for a one-time $1,000 bonus. The tutorial state is saved with your profile; older profiles can complete it too.
- **Plot themes and titles:** choose **UPGRADES → PLOT THEMES**. Themes unlock at rebirth 0, 10, 25, 50 and 100 and are cosmetic. Rebirth titles appear above your character automatically.
- **Rare announcements:** Mythic or higher roll offers can be announced to the current server. An announced offer has not necessarily been purchased.
- **Catalog and odds:** from **REWARDS → CATALOG & ROLL ODDS** (or the roll station), browse all 50 archetypes, search by name and filter by rarity or unlock status. The server supplies a timestamped snapshot of current per-slot rarity odds and active weight bonuses. Each unlocked archetype is equally likely within its rarity; the catalog shows that per-archetype chance for any part or mutation. Refresh after rebirth, an event change or a boost expiry. Part type and mutation probabilities are shown separately; they are not included in the per-archetype number. Listed prices are before the Eclipse discount. Session gift odds differ from regular rolls.
- **Auto-roll:** at rebirth 5 (or earlier with a configured AutoRoll pass), open the roll station and choose **CONFIGURE AUTO-ROLL**. Set each rarity to **Skip** (discard that offer), **Hold** (stop and keep it for review) or **Buy** (spend cash). Set a total cash budget, per-part maximum and a batch limit, then review and confirm. Defaults skip Common/Uncommon and hold all other rarities, so they do not automatically buy anything. Existing offers must be bought, skipped or deliberately discarded before starting. The server checks your settings and processes slots in order every two seconds. It stops at Hold, on insufficient cash, capacity or a limit, when you move away, or when its entitlement is lost. The current and later offers remain for manual review, but still expire after 60 seconds. Skip only discards unpurchased offers; it never deletes owned inventory. A new run resets the limits; manual purchases are not counted against them. Auto-roll never uses vouchers. Settings and counters are session-only, not saved.
- **Rebirth safety:** open **REBIRTH**, select the exact matching, unprotected, non-ascended creature you want to sacrifice, then request a server review. Check its level, stand, components, wallet reset, roll slots and unpurchased offers before confirming. The one-use review expires after 30 seconds; changes to the shown details, cash, offers or Keep Slots entitlement require a new review. Stop auto-roll first. Rebirth removes the selected creature and resets all wallet cash; pending bank cash, other inventory and stands remain. A placed sacrifice is removed from its stand. The server verifies everything again at confirmation.
- **Plot automation:** at rebirth 10, open **UPGRADES** and turn on the free auto-collector. While you are in the main place, it transfers whole pending dollars to your wallet about every 10 seconds; it uses the same collection and quest rules as the ATM. Your setting is saved, but the timer starts fresh each time you join. It does not collect offline or in the hub. The paid shortcut from the specification is not implemented.
- **Income breakdown:** open **UPGRADES → PLOT INCOME BREAKDOWN** to see estimated normal, current online and offline rates and active income bonuses. The normal rate includes levels, ascension adjacency and the Sigma Statue. The online estimate also includes active Sigma/weekend events and verified VIP. Offline is 25% of normal for up to 24 hours and excludes events, VIP and EXP. Server delays can reduce actual online earnings.
- **Crafting large inventories:** at the assembly pod, choose a socket, then search, sort and page through eligible parts. Protected parts are hidden; the blueprint toggle limits results to Rare+. The fusion forge searches and pages eligible creatures and narrows the list to the first selected recipe. Stand menus search and page unplaced creatures; remove the current occupant first. These views are previews: the server rechecks ownership, eligibility and the complete recipe before any changes.
- **Backpack filters and batch protection:** filter by rarity, mutation and (on the Brainrots tab) placement as well as search and protection. A creature matches a mutation if any component has it. Review **Protect** or **Unprotect** for the filtered matches across all pages, inspect the captured items on the review pages, then confirm or cancel. The server rejects the whole batch if an item is missing or its protection state changed. This protects items; it does not sell them. The separate bulk-sale action still ignores browsing filters.
- **Backpack inspection:** select a part or creature to review its rarity, mutation, protection and resale value; creature details include its four components, level, base income, blueprint/ascension and stand. Search also finds creature component names and mutations. Cash level-ups require a review and confirmation; the server rejects the request if the creature's level or quoted price changed. Protected creatures can still be leveled, but protected items cannot be sold or consumed.
- **State refresh:** the main game requests a fresh server snapshot while loading and every 30 seconds thereafter. You can also select **REWARDS → REFRESH GAME STATE FROM SERVER**. Incoming updates are held visually while you type in a menu field; the server remains authoritative. A request may be throttled and retried at the next interval.
- **Accessibility:** open **REWARDS → ACCESSIBILITY SETTINGS** to reduce creature display motion and particles, mute this game's local sound effects, or hide event color tint. The showcase hub has its own **ACCESSIBILITY** button for display motion. These are local, session-only settings; they reset on rejoin or place change and do not change gameplay. The HUD and menus adapt to the available GUI area, but still need testing on real mobile devices and screen-reader support is not implemented.
- **Creature displays:** placed and showcased creatures use asset-free procedural faces, headwear, chest details, hands and feet derived from the four component archetypes. Level 5 adds glowing eyes; level 10 adds a rarity-colored halo; ascended creatures also have a crown. Stand labels show rarity, level and normal stand income. These are geometric placeholders, not custom R6/R15 rigs or licensed character art. Cosmetics do not change gameplay. More display parts may affect performance, so test full servers and mobile devices.
- **Assembly preview:** choose four unprotected owned parts at the pod to see the predicted creature name, rarity, level-1 income and whether matching mutations grant the 2x harmony bonus. Review and confirm before consuming parts. This preview is informational; the server rechecks ownership, protection, capacity, blueprint requirements and the calculation at confirmation. In the fusion forge, select a creature to inspect its component recipe and projected output before confirming.
- **Auto-fill:** in the assembly menu, this finds the highest-income four-part combination among unprotected parts in your current inventory, including the identical-mutation bonus. You can change the selection before assembling.
- **Fusion forge:** at rebirth 15+, use the orange forge in the plaza. Select three different, unplaced, non-ascended creatures at level 10 or higher with exactly matching four components and mutations. Confirming permanently consumes all three and the displayed cash fee. The result starts at level 1 with five times one input's base income. Place it to boost each occupied neighboring stand by 20%; boosts from multiple neighbors add. Rebirth sacrifices require a non-ascended creature. See the [forge guide](docs/FUSION.md) before using it.
- **Extra stands:** buy stands 13–24 in UPGRADES. Stand 13 requires rebirth 1, stand 14 rebirth 2, and so on. Your extra stands persist through rebirth.
- **Backpack:** use the All, Body Parts, Brainrots and Boosts tabs. Search names, part types or mutations and press **APPLY SEARCH**; filter by protection, sort, and page through results. "Newest" is based on inventory order within each category, not a global acquisition timestamp. Select an item and press **PROTECT** to prevent accidental selling or consumption; press **UNPROTECT** to use it again. Protection is saved and enforced by the server against single/bulk sales, assembly, fusion and rebirth sacrifice. You can still place and level a protected creature.
- **Selling:** choose an unprotected item in BACKPACK and confirm the sale. For bulk sales, select a maximum rarity and request a server review. The safer default includes only unprotected Standard parts (including legacy parts without a mutation); switch to **ALL mutations** only if you intend to sell rarer mutations too. Bulk sale ignores search, browsing filters and inventory pages. Read the complete paginated item list and total before confirming; the fixed review expires after five minutes, and any changed or protected selected item cancels the whole sale. Newly acquired parts are not added to an existing review. Remove a creature from its stand before selling it. Sales are permanent; a creature resells for half the total original prices of its four parts.
- **REWARDS** opens daily rewards, quests and nine timed session gifts; its **HOW TO PLAY** button explains the loop. Plaza leaderboards show only the current server, not all players worldwide. Roll offer odds are for a rarity tier, not a specific item or mutation.
- **Developer admin:** disabled by default. Trusted developers can configure their numeric user IDs and use a server-checked test menu; see [the admin guide](docs/ADMIN_SETUP.md). Its actions can change real saved data.
- **Gamepasses:** the shop is under **UPGRADES**. All pass IDs are zero by default, so purchases are disabled. See [gamepass setup and limitations](docs/GAMEPASS_SETUP.md) before changing them.
- **Showcase hub:** there is a disabled-by-default portal to a separate place with 15 booths. Configure it using [the hub setup guide](docs/TRADING_HUB_SETUP.md). Booth owners can search, sort and page their creature list, hide already displayed items, and review before releasing a booth. Visitors see the displayed creatures’ component details; use Refresh to fetch changes. There are no sales or trades yet.
- **Audio:** the game is silent by default. To add sounds you have permission to use, replace the `0` values in `Config.AudioIds` in `src/shared/Config.luau` with your Roblox audio asset IDs; sync using Rojo. Roblox must allow your experience to use the assets.

### Daily rewards, session gifts and offline cash

- Open **REWARDS** for daily login rewards and three daily objectives. UTC midnight starts a new day; missing a day resets the seven-day streak. The seven rewards are $1,000, three 15-minute 3x luck potions, Golden Lever, $50,000, three free-part vouchers, $250,000, and Sigma Statue. Duplicate lever/statue unlocks pay $5,000/$100,000 instead. Existing cash-only streaks continue from their saved day; past claims are not changed retroactively.
- The Golden Lever multiplies non-Common rarity weights by 1.05, not the final probability. The Sigma Statue multiplies stand income (including offline income) by 1.5. Potions multiply non-Common weights by 3 for 15 minutes; active potions add duration, and combine with other weight boosts. These items and expiry times are saved with the profile. The visuals are simple procedural placeholders.
- Nine session gifts are claimable at 1, 3, 5, 10, 15, 25, 40, 60 and 90 minutes: $500, five free-part vouchers, a random Uncommon part, $15,000, a 10-minute 2x luck boost, a rare assembly blueprint, $100,000, a random Epic+ part, and the Ohio Crown. An already-owned crown pays $100,000 instead. Session timers and claims reset on leaving or entering the hub; rejoining allows gifts to be earned again, so this needs economy balancing before release. Part gifts require space and can bypass normal rebirth unlocks. The Epic+ gift uses fixed weights 600:200:50:10:1 for Epic through Secret, unaffected by luck, and always has Standard mutation. Three unspecified gift tiers remain unimplemented.
- **Free Standard Roll Crates:** open earned crates under **REWARDS** or **BACKPACK → Boosts**. Each gives one Standard part: 80% Common and 20% Uncommon, with an equal chance of each archetype within the selected rarity and 25% per part type. Luck and rebirth do not affect these odds; some parts may be above your rebirth unlock. A crate requires free part space, caps at 100 stored crates, and is not consumed on a failed grant. There are no paid crates.
- **Quest consumables:** use 2x luck potions and open Uncommon Mystery Boxes under **REWARDS** or **BACKPACK → Boosts**. Each free box gives one Standard Uncommon part; all seven Uncommon archetypes and four part types are equally likely (1 in 28 per combination), independent of luck and rebirth. It may grant an archetype above your current rebirth. A box requires a free part slot and is not consumed if opening fails. Potions extend the existing 2x boost duration, which stacks with an active 3x boost as non-Common rarity *weight* multipliers. Both saved inventories cap at 100; a full inventory blocks its daily quest claim, and unclaimed quests reset at UTC midnight. No paid boxes are available.
- **Rare assembly blueprint:** claim the 25-minute gift under **REWARDS**. At your assembly pod, turn **RARE BLUEPRINT** on, select four unprotected Rare-or-better parts, and review and confirm. One saved blueprint is consumed and the creature gets 25% more base income; the bonus combines with the existing matching-mutation bonus and is included in stand/offline calculations. Auto-fill respects the rarity requirement. Blueprint creatures must match other blueprint creatures to fuse. Blueprints cap at 100; if full, use one before claiming the gift. This is a prototype interpretation because the specification does not define the blueprint recipe.
- **Backpack upgrades:** open **UPGRADES** to buy up to ten permanent +5 part-slot upgrades with in-game cash. They start at $5,000 and double each tier, for a cash-upgraded capacity of 100–150. Claimed season tiers 10, 30 and 50 each add five more slots; the optional configured Backpack pass adds 100 (maximum 265). Creature capacity stays 100. If pass ownership is unavailable, existing extra parts are preserved but new purchases may be blocked until verified. Upgrade prices and limits are prototype balance choices.
- Rolls already cost nothing: a **free-part voucher** instead buys one currently displayed offer without cash. At the roll station select the voucher button for a part before the offer expires; normal distance and inventory limits apply. Vouchers can be used on expensive parts, which retain their normal resale value. Potions are used from **REWARDS**; saved boosts continue counting down while offline. Inventories cap at 100 potions and 1,000 vouchers; use some before claiming a reward that would exceed the cap.
- **REWARDS → OPEN FREE SEASON TRACK** shows a prototype 50-tier free track. Every 100 season XP unlocks a tier; claim tiers in order. Each rolled part earns 1 XP, each assembly 20, each rebirth 100, and the three daily quest claims add 50, 75 and 100 XP. Progress starts when this update is installed, is not retroactive, and is capped at 5,000 XP. Tiers 10, 30 and 50 give permanent +5 part slots each; other multiples of six grant a Standard Roll Crate. The remaining tiers use the original three-tier cycle of cash ($1,000 times the tier number), a 3x potion, and two free-part vouchers. Preview all 50 rewards in the menu. Existing claimed tiers 10/30/50 automatically receive their slot bonuses; previous cash or voucher rewards are not removed, and crates are not granted retroactively. Use inventory items first if a claim would exceed a cap. This is a permanent prototype track, not a time-limited season; premium rewards are not implemented.
- The same screen has a repeatable objective: roll 250 body parts and claim one free-part voucher. Multi-slot pulls count each generated part, including offers you don't buy; excess progress carries over, up to 250,000 unclaimed rolls. The requested multi-roll token is substituted by a free-part voucher because rolls already cost nothing. Each UTC day the server randomly chooses one target per category: roll 30/40/50 parts for $10,000 and 50 XP; assemble 1/2 Rare+ creatures for one saved 10-minute 2x luck potion and 75 XP; collect $100,000/$250,000/$500,000 for one Uncommon Mystery Box and 100 XP. The 18 target combinations are equally likely; the same combination can repeat. Rewards do not vary by target. The selection and progress persist when saved; failed saves can lose progress or the selection. Existing active fixed quests stay unchanged until the next UTC reset, and previous claims are not changed retroactively. Claims are tied to the displayed UTC day so a delayed request cannot claim a new day’s quest.
- **Online income timing:** placed creatures accrue income and level progress using elapsed server time rather than assuming every tick lasts exactly one second. Earnings are settled before stand changes, collections and relevant upgrades, and the calculation accounts for level-ups within an interval. Each checkpoint caps catch-up at 30 seconds; longer server stalls can still lose income, and scheduled event transitions are approximated to the next checkpoint. Offline income is calculated separately below.
- Your placed creatures earn 25% of their normal base stand income while you are away, for up to 24 hours. This amount is added to your pending bank when you return to the main place. A welcome-back receipt shows the credited amount, counted time, estimated rate and whether the cap applied; reopen it during the same session under **UPGRADES → PLOT INCOME**. It is informational, not a second claim. Adjacent ascension bonuses and Sigma Statue are included; event/VIP multipliers and offline EXP are not. If a server crashes or the final save fails, offline time may not be recorded.
- **REWARDS → LIVE EVENT SCHEDULE** shows the current or next scheduled window for each event and explains its effect. The server supplies a UTC snapshot; countdowns are estimates, so refresh after a window passes. A temporary developer override is server-only and may change after the snapshot. This schedule is informational and does not grant rewards or predict future overrides.
- Events use a shared UTC schedule across servers. Every Friday 17:00 UTC through Sunday 23:59 UTC, Weekend Frenzy increases non-common rarity weights by 1.5 and stand income by 2. See the roadmap for how multipliers stack.

## Saving and Studio testing

**Important deployment step:** update and publish both places with this version, then shut down old servers before testing or opening access. Older servers cannot load inventories over 250 parts and may mishandle expanded profiles. Back up test data and never mix versions during rollout.

- Published servers attempt to save in Roblox DataStore `RollABrainrotProfiles_v1`, with a session lease, periodic saves, retries and a shutdown save. A failed load kicks the player instead of silently overwriting data. Offline income requires a successfully recorded departure; it is capped at 24 hours and is credited atomically when loading the main place.
- **Studio defaults to temporary in-memory data**, so progress resets on leaving. To test real persistence, publish a **separate test experience**, enable **Game Settings → Security → Enable Studio Access to API Services**, then set `DataService.TestPersistence = true` in `src/server/Services/DataService.luau` and sync with Rojo. Studio API access can affect the published experience's actual data, so never test on your live game. Set the flag back to `false` after testing.
- Save requests take isolated snapshots before waiting, and older queued autosaves cannot overwrite a newer completed save. A final save supersedes queued autosaves. Profile loading rejects malformed inventory arrays, empty item IDs and malformed lease metadata rather than silently discarding data; an affected player must not be reset automatically. These are safeguards, not proof against every service failure.
- Both places stop accepting new joins during shutdown and wait up to 25 seconds for in-flight joins and final saves. Saves reject invalid profile snapshots and report copy failures instead of leaving a save permanently busy. These safeguards cannot guarantee saving if Roblox stops the server or DataStore requests fail. Verify rejoin, overlapping joins, two concurrent sessions, save errors and shutdown in the test experience before trusting the system with real players. Roblox services can fail; unsuccessful final saves can lose progress.

## Troubleshooting

- **No world or UI:** check Rojo connection and press Play, not Run. Open **View → Output** for errors. The synced locations are ReplicatedStorage/Shared, ServerScriptService/Game and StarterPlayer/StarterPlayerScripts/GameClient.
- **Cannot roll or assemble:** use your own plot and stay within 20 studs of the station. The prompt opens the menu; use its button to act.
- **Cannot buy:** check your balance and body-part capacity (100–150 with cash upgrades, plus up to 15 season slots; a configured Backpack pass adds 100). Rerolling discards unpurchased offers, and remaining offers expire after 60 seconds.
- **Kicked while loading:** DataStore may be unavailable or the previous server's lease is still active; wait a few minutes and retry. Check Output for errors.
- **Studio data resets:** this is the default. See the saving section above.

The catalog contains names that may involve third-party intellectual property; review names and obtain appropriate rights before publishing.

For a more detailed step-by-step verification list, see [Studio testing](docs/TESTING.md).
