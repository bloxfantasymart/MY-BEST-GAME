# Progress and roadmap

## Implemented development build
- A tiled 2,500 × 2,500 grass footprint, six 120 × 120 spaced plots with radial paths, simple non-colliding trees/rocks/wildflowers, a decorative lake and river with walkable bridge decks, boundary cliff blocks, atmosphere/bloom and a 24-minute lighting cycle. The landscape is placeholder parts, not Smooth Terrain, swimming water or final-quality rivers/bridges, and needs device/physics testing. Procedural plaza, six assigned plots, roll station, assembly pod, ATM and 12 starting stands, expandable to 24. Creature displays use geometric, asset-free component-specific faces, headwear, chest plates, hands and feet, with basic idle motion and mutation effects. Level 5 adds neon eyes and level 10 adds a rarity halo; ascended units add a crown. Rarity-colored stand and hub labels show level and base income. These are still placeholder geometry, not R6/R15 rigs or final art. Roll trays, lever motion, ATM pad, a collection effect, a help panel, server-only leaderboards, and optional configurable sound hooks are included.
- A six-step tutorial follows server-verified rolls, purchases, assembly, placement and collection; completing it grants a one-time $1,000 bonus. Its saved step is added to older profiles on first load. The client shows a static station marker and highlight, dynamically chooses an empty stand, and can hide world markers while retaining the written goal. Protected parts do not count as usable assembly inputs; guidance recovers if needed parts or creatures are lost. This marker is not pathfinding. Existing players can also complete the tutorial once.
- Cosmetic plot themes unlock at rebirth 0, 10, 25, 50 and 100; the selected theme persists. Avatar titles update at the same milestones in both places. These are simple procedural colors/materials, text and nearby cosmetic auras, not final artwork or map-wide particle auras.
- A developer admin menu is disabled by default and gated by configured Roblox user IDs on the server. It can inspect online player inventories, adjust cash/rebirth, grant a Standard part, kick and trigger a 120-second server-only event. Actions require confirmation in the UI, validate numeric input and write basic non-durable output logs. Offline administration, persistent bans, creature grants and cross-server controls remain unimplemented. See `docs/ADMIN_SETUP.md`.
- Main-place clients retry initial state requests, reconcile observed revision gaps, request a server snapshot after 30 seconds without a full update and expose a manual refresh in Rewards. Server-driven redraws wait while a menu text field is focused. This is a RemoteEvent-based refresh, not the specification’s named RemoteFunction; actual network behavior needs Studio testing.
- Main and hub interfaces calculate layouts from their available GUI area, resize the HUD/navigation/panels on viewport changes, and use wrapped, constrained text. Main-place accessibility settings can reduce display motion/particles, mute local game sound effects and hide event tint; the hub has a reduced-motion control. Preferences are local and session-only. This is not screen-reader support and requires actual device, safe-area and orientation testing.
- Client display animation and basic Fire/Sparkles effects are disabled beyond 100 studs, with streaming-aware checks for required display parts. This is a lightweight LOD: distant geometry remains present, and the added visual details increase part counts. It is not a substitute for full device/streaming performance testing.
- Mythic, Godly and Secret offers can be announced to the current server, with a five-second server-wide throttle. Announcements describe offers, not purchases; best-effort Godly/Secret cross-server banners are rate-limited and cosmetic.
- A searchable, paginated catalog shows all 50 archetypes, rarity, rebirth unlock, base part price and contribution. A saved, server-recorded collection index tracks the four acquired part types per archetype, including creature components; it has progress totals and missing/started/complete/unseen filters but no rewards or mutation tracking. Offers do not count. Existing owned items are scanned, but items no longer present in inventory or creature components before the update cannot be reconstructed. Old/unknown names are retained within a 200-name cap; failed saves can lose progress. Its timestamped server-supplied roll-odds snapshot uses the same weight calculation as the roller and displays active weight modifiers, per-tier/per-archetype chances, and separate part and mutation probabilities. Snapshots need refreshing after changes and do not describe session gift odds.
- Server-generated rarity-weighted rolls and mutation rolls, four part types, 50 catalog rows, nine slot prices, purchase/assembly/placement/income. Remote actions are throttled and physical station actions check proximity.
- The assembly pod provides selectable sockets, literal search, sorting and 12-item pages over eligible parts, and previews creature name, rarity, level-1 base income, mutation harmony and optional blueprint use before an explicit confirmation. Crafting and fusion require 60-second, one-use server reviews of the exact inputs and output (plus fusion fee); the server replans and compares all captured attributes without yielding before committing. The initial client preview is informational and shares the calculation, not authority. The forge searches and pages eligible creatures, filters candidates by the first selected exact recipe and shows that recipe and projected 5x base output; client and server share the recipe comparison but the server still validates everything. Stand menus search, sort and page unplaced creatures and always show the current occupant for removal. A shared adjacency calculation previews normal total and affected-stand income before a player confirms placement or removal; estimates include Sigma Statue but exclude event/VIP multipliers. The server requires explicit place/remove intent, rechecks stand occupancy and ownership, and settles income before mutation; stale estimates are informational. Both reject failed or colliding generated IDs before consuming inputs.
- Mutation weights: Standard 90%, Shiny 7%, Golden 2.4%, Void 0.5%, Glitched 0.1%. Each part's base contribution is multiplied by its mutation multiplier (1, 1.5, 2.5, 4 or 6); four identical mutations, including Standard, double the result. The sum is multiplied by the highest rarity multiplier and 0.4. Ties choose Head, Chest, Arms, Legs order. Effects are basic built-in sparkles/fire and client-side rainbow color, not final artwork.
- The plaza fusion forge unlocks at rebirth 15. It consumes three distinct, unplaced, non-ascended creatures at level 10 or above whose four components and mutations match exactly, plus a fee of `max(10000, floor(base income * 100))`. The result starts at level 1 with 5x one input's base income and a cosmetic crown. Each ascended creature boosts occupied north/south/east/west neighboring stands by 20%; bonuses add and never wrap across rows. Base stand labels include these bonuses but not temporary events or VIP. Offline income includes adjacency at its normal 25% efficiency. Unlike the spec's proposed max level 10, this build caps levels at 1,000 and accepts level 10 or above. Rebirth will only sacrifice non-ascended creatures. Fusion is irreversible.
- At rebirth 10, an optional free auto-collector can collect whole pending dollars every 10 seconds while in the main place, using the ordinary ATM/tutorial/quest collection path. The on/off setting persists, the interval restarts on join, and the simple drone visual is removed when disabled or when the player leaves. The paid shortcut is not implemented. An income panel shows estimates for current, normal and offline earnings and active income multipliers. Online earnings and fractional level progress use elapsed monotonic time, settled before relevant mutations and saves; each checkpoint catches up at most 30 seconds, and event changes between checkpoints are approximate.
- Placed creatures gain one level per 10 seconds and can also be upgraded with cash from the backpack; +25% of base income per level. This interprets the unspecified EXP threshold as one EXP per level. Level cap 1,000 and creature cap 100 are safety choices. Offline EXP is not included.
- Up to 100 rebirths. Requirement is floor(1000 * (current rebirth + 1)^2.7). Rebirth 1 requires Dirt Boy; subsequent targets use the last catalog entry unlocked at the **current** tier, so the sacrifice can be obtained before rebirthing. Players select the exact unprotected, non-ascended target and receive a 30-second, one-use server review with creature components, cash, slots and unpurchased offers. A changed review is rejected. Cash and roll slots reset, the selected creature is removed (including from a stand), and other inventory, stands and pending cash remain. Auto-roll must be stopped before review. No paid skips yet. A configured KeepSlots gamepass can retain slots.
- UTC-synchronized events: each 30-minute period starts with a five-minute Frenzy that doubles non-common tier weights. At each 15-minute boundary the disaster alternates deterministically among Eclipse (3 min), Sigma (2 min), and Ohio Storm (2 min). Eclipse discounts newly rolled offers 50%; Sigma triples stand income; Storm spawns collectible golden drops near each plot every 10 seconds, each giving its owner $50 times (rebirth + 1) and one scrap, subject to the scrap cap. Every Friday 17:00 UTC through Sunday 23:59:59 UTC, Weekend Frenzy multiplies non-common tier weights by 1.5 and income by 2. Frenzy and weekend luck factors multiply; Sigma and weekend income factors multiply. The client adds a simple event tint. Rewards includes a manually refreshed server-generated UTC schedule with estimated countdowns, effect explanations and current server-only override disclosure. These snapshots can become stale. This is a deterministic global schedule, not randomized disasters or cross-server messaging.
- Nine per-session gifts exist at 1, 3, 5, 10, 15, 25, 40, 60 and 90 minutes; each also has a saved one-claim-per-UTC-day limit; see the README for contents, blueprint rules, odds and save-failure caveats. Three unspecified tiers remain unimplemented.
- Unpurchased roll offers expire after 60 seconds; the server rejects late buys even if a client display is stale. Manual reroll is blocked until all offers are resolved; the client reviews individual skips and the exact list for bulk discard, and the server checks the discard IDs and order against current offers. The limited-time luck boost multiplies non-common rarity weights and stacks with weekend, Frenzy and pass weights, not necessarily the final rarity probabilities.
- The seven-day UTC login calendar now grants cash, 3x luck potions, multi-roll tokens, Golden Lever and Sigma Statue; duplicate permanent unlocks pay cash. Three daily objectives have server-randomized targets: roll 30/40/50 parts, assemble 1/2 Rare+ creatures, and collect $100,000/$250,000/$500,000. The 18 combinations are equally likely; fixed category rewards are $10,000, a 10-minute 2x luck potion, and a free Uncommon Mystery Box respectively, plus 50/75/100 season XP. The choice is saved with progress, resets at UTC midnight and can repeat; an unsaved crash can lose it. Active legacy quests keep their original targets until their next reset. The box gives one uniformly chosen Standard Uncommon archetype and type regardless of rebirth, subject to inventory space; both consumables cap at 100. This randomizes target sizes, not objective categories; paid boxes are not implemented.
- A permanent prototype 50-tier free season track grants cash, 3x potions, vouchers, free Standard Roll Crates and +5 part slots at claimed tiers 10, 30 and 50. Other multiples of six award a crate; remaining tiers follow the earlier three-reward cycle. Existing claimed milestones receive slots retroactively, but crates are only for future claims. Crates yield 80% Common / 20% Uncommon, uniform archetype within tier, 25% each part type, Standard mutation and no rebirth/luck influence. Claims are sequential, caps are checked first, and XP is not retroactive. A repeatable 250-rolled-parts objective awards one multi-roll token. No seasonal reset or premium track is implemented; see README for limits and update requirements.
- On a successful main-place departure save, the logout time is recorded. Main-place load atomically adds 25% of placed-creature income including adjacency bonuses for up to 24 hours to pending cash, then clears the timestamp while acquiring the lease. The hub retains the timestamp, so time in the hub counts as away. A session-only welcome-back receipt shows the credited amount, counted time, offline rate and cap status; it can be reopened from the income panel and never pays again. Event and VIP multipliers and offline EXP are not included. A crash or failed departure save may prevent offline earnings.
- Persistence uses a DataStore profile with an UpdateAsync lease, 45-second renewal/autosave, retries and shutdown flush. Both places gate duplicate/in-flight joins and new actions during shutdown, attempt to release profiles acquired after shutdown begins, and wait up to 25 seconds for joins, shutdown saves and departure saves already in flight. Saved snapshots are copied before waiting, out-of-order queued autosaves cannot overwrite newer completed snapshots, and final saves supersede queued autosaves. Sparse/mixed inventory arrays, empty item IDs and malformed lease metadata are rejected without replacing profiles. Studio defaults to memory-only; see README. It is a first implementation, not a proven production persistence library. A server that cannot renew for 120 seconds stops gameplay by kicking the player; the 180-second lease eventually expires after a crash. A failed final save may lose progress. New data starts at $200; the part price is max($10, base income * 5), discounted in Eclipse. These are prototype choices.
- Ten in-game cash backpack upgrades add five part slots each, permanently raising the base capacity from 100 to 150; claimed season milestones add up to 15, and a verified optional Backpack pass adds 100 more, for a maximum of 265. Upgrades survive rebirth. The creature cap remains 100 and a loss of pass verification never removes existing parts. The 25-minute gift awards one rare blueprint: using it with four Rare+ parts adds 25% to creature base income; a blueprint-boosted creature can fuse only with matching blueprint-boosted creatures. Both are prototype interpretations and require balance and Roblox testing.
- Auto-roll unlocks at rebirth 5 or through the optional configured AutoRoll pass. Every two seconds it processes each rolled slot in order according to per-rarity Skip/Hold/Buy rules, with server-validated cash budget, per-offer cap and batch limit. Shiny, Golden, Void and Glitched default to Hold regardless of rarity, or can be set to follow the rarity rule. Automatically bought non-Standard parts are protected by default (optional opt-out); manual cash/voucher purchases have their own default-on, session-only protection setting and an explicit opt-out review. Hold and limit failures stop the run and retain the current and later offers for up to 60 seconds; Skip discards offers, not owned parts. It stops on lost entitlement, distance or full capacity. Settings are session-only; no super-speed pass or inventory auto-delete is implemented. Inventory supports search (including creature component names and mutations), protection/rarity/mutation/placement filters, sorting, 20-item pages, a boosts tab, item/component inspection, confirmed sales and rarity-based bulk sales. Filtered matches can be batch protected or unprotected after a paginated review of the captured IDs; the server validates the whole batch without yielding and rejects stale protection states atomically. Batch protection respects filters, but bulk sale deliberately ignores them. Individual sales use a 60-second one-use server review with the exact part or creature and its components, rechecked before removal and credit; changed items, placement, protection or value reject the sale. Cash level-ups show a review and require the server to match the reviewed creature level and price before spending; stale or replayed confirmations are rejected. Server-enforced saved protection blocks sale, assembly, fusion and rebirth sacrifice; protected creatures can still be placed and leveled. Bulk sales default to Standard-only, with an explicit all-mutations option, and ignore browsing filters. A five-minute, one-use server quote provides a paginated list and total for up to 265 eligible parts; confirmation revalidates every captured item and its resale value before any removal. New items are not added to an existing quote. Part resale pays 50% of its original offer price; creature resale pays 50% of the four parts’ original prices (to prevent crafting/reselling from creating cash). Placed creatures cannot be sold. Auto-fill searches for the highest-income four-part combination under the implemented formula, including mutation harmony and excluding protected parts; the server still validates the chosen parts.
- A small optional nine-platform summit parkour course uses ordered server-observed touches, basic position/timing checks, character-bound attempts and a summit prompt. A successful claim grants $50,000, three multi-roll tokens, and a 10% chance of a protected Peak Mountain Head. The head is a prototype Rare Standard part with $50/s contribution and $10 recorded price; it is exclusive to the summit and excluded from the normal rolling catalog/collection index. A free part slot is required for every claim and token caps apply. The saved cooldown is six hours; failed ID generation holds its draw until a successful claim within the same session. Unsaved crashes or failed saves can lose reward/cooldown, and leaving clears a pending draw. This is placeholder geometry, not the specified mountain. Position/timing checks are not complete anti-cheat, so the reward requires private Roblox physics, persistence and exploit testing before release.
- Three saved stand layouts store creature IDs and stand numbers, not copies; saves and deletes require an explicit reviewed snapshot and proximity to the assembly pod. Applying requires a 60-second one-use server quote with every changed stand and estimated normal income. The entire target and current layout are revalidated before an atomic, no-yield rearrangement; missing creatures or locked stands reject the operation. Current occupants absent from the target become unplaced, including protected creatures. Income is settled before the change. Layouts persist with successful profile saves and can become stale after sales, fusion or rebirth.
- Twelve extra stands unlock one at a time with cash and rebirth milestones. First costs $2,500 at rebirth 1; each following stand doubles the previous price and requires one additional rebirth. Extra stands survive rebirth. Limited plot teleport buttons have a server cooldown.
- Five optional gamepass hooks are disabled by default. When configured and confirmed by Roblox server-side ownership checks, Luck doubles non-common tier weights, AutoRoll unlocks auto-roll before rebirth 5, KeepSlots retains roll slots on rebirth, Backpack adds 100 body-part slots to the cash- and season-upgraded capacity, and VIP adds 20% online stand income. Luck stacks multiplicatively with event weights and VIP stacks with event income multipliers. VIP chat/booth cosmetics and VIP offline bonuses are not implemented. Developer products remain disabled. Ownership-query failure is treated as unknown; a potentially destructive rebirth is blocked if KeepSlots has not been confirmed. A confirmed KeepSlots entitlement is also retained in the saved profile to protect slots against later configuration/service failures. Never configure paid features for public sale until Roblox tests pass; see `docs/GAMEPASS_SETUP.md`.
- A separate 15-booth showcase hub can be configured with two place IDs; players claim a booth, display up to four owned creatures and inspect rarity, level, components, mutations, blueprint/ascension and standalone income. Owners can search, sort and page their own inventory, hide displayed creatures and confirm booth release. Visitors refresh manually for changes; the full owner inventory is not sent to visitors. The hub loads the same locked profile without changing its inventory. Booths are temporary; return and entry portals require published places in the same experience. **There are no transactions, prices or item transfers yet.** See `docs/TRADING_HUB_SETUP.md`.

- The current luck model multiplies rarer tier weights increasingly with 1.15 compound rebirth luck; it is not a guarantee of a particular rarity. Probabilities depend on unlocked tiers. Slots and HUD collection are usable from anywhere. Offer text shows the tier chance at roll time, not the probability of a specific archetype, body part or mutation.

### Interaction abuse safeguards
Main-place and showcase-hub prompts now have a per-player rate limit separate from remote actions, after ownership/health/proximity checks. Excessive bursts are temporarily blocked per channel. This is a server-side traffic safeguard, not a substitute for Roblox multiplayer and exploit testing.

### Reconnect safety
A new connection is rejected while the same user's prior join or departure is still in progress on that server; duplicate callbacks for the same player are ignored. The profile service also rejects concurrent local loads or a load while a local session exists. A rejected final snapshot is not saved and may leave a lease until expiry. These safeguards cannot prevent lost progress after a failed final save or replace live DataStore testing.

### Inventory safety overview
The backpack has an all-inventory overview with capacity, protection, placed and mutation counts, unprotected part types and indicative sale totals. It can capture all unprotected mutated loose parts and mutation-containing creatures into the existing paginated batch-protection review, including placed creatures. Confirmation revalidates ownership and protection atomically on the server; the snapshot and estimates are not sale quotes. This UI needs Roblox device and multiplayer testing.

### Waterfall altar prototype
A small walk-through waterfall/cave and altar offer a free, server-owned 10-minute 1.5× non-Common weight blessing. It stacks multiplicatively with other roll-weight boosts, is shown in odds disclosures and the HUD, and resets on leaving; refreshing resets the timer with a 30-second interaction cooldown. The geometry is a small placeholder and is not the requested expansive mountain terrain. Actual Roblox accessibility, physics, effects and multiplayer behavior remain untested.

### Multi-roll token prototype
A saved token produces nine temporary offers regardless of unlocked permanent slots; parts still cost cash or separate vouchers, and unused offers expire after 60 seconds without a token refund. The day-five calendar reward, 250-roll repeatable objective and summit award tokens going forward. The maximum is 1,000; old vouchers remain unchanged. The batch and token deduction commit only after all offers are created. This interpretation needs economy and Roblox testing; roll slots remain valuable for ordinary and auto-roll. Update and publish both places and shut down all older servers before enabling the changed schema.

### Treasure and scrap prototype
Ten first-come chests spawn at randomly chosen outer-valley positions for each 15-minute server round. Each yields $500 × (rebirth + 1) and three scrap; a saved limit allows ten chest claims per UTC day per player. Owner-only Ohio Storm drops yield $50 × (rebirth + 1) and one scrap. Scrap caps at 1,000,000; its cap blocks both rewards. At the assembly pod, a one-use 60-second server review converts 100 scrap per Uncommon Mystery Box, up to ten per batch, with atomic resource/cap revalidation. Boxes are opened separately. The quota and resources depend on successful saves, so crashes can lose rewards and permit repeats. Locations, prices and box art are prototypes; proximity checks are not complete anti-cheat. Update both places and shut down old servers before rollout; Roblox testing and balancing remain required.

### Expanded world prototype
Six plots are 350 studs from the plaza and retain their existing stations, stands and progression. Exploration chests spawn on a 625-stud radius; a travel button reaches the outer valley. Ground tiles avoid oversized parts, scenery is non-colliding, and basic perimeter cliffs bound ordinary walking. The lake and river are decorative rather than swimmable; the waterfall and summit remain small placeholders. Day/night uses a server-synchronized 24-minute cycle updated every ten seconds. This is not the requested finished biome, terrain, animation or bridge system; map performance, reachability, camera behavior, lighting and multiplayer must be tested in Roblox.

### Rare-roll announcements
Mythic+ server announcements describe an offer, not a purchase, and the displayed approximate odds are for the rarity tier alone. Godly/Secret offers may additionally send a validated cosmetic MessagingService banner to other gameplay servers. The server limits publishes to one per 60 seconds and display to one per five seconds; messages have bounded deduplication, reject malformed catalog/type indices and expire after two minutes. Delivery is best-effort; subscription retries three times, and no message ever modifies inventory or currency. Roblox Studio does not use the cross-server channel. A session-only accessibility toggle hides banners, and `Config.CrossServerAnnouncements` disables cross-server traffic. Test real MessagingService behavior in private published servers; this is not a durable global feed or authenticated audit trail.

### Event presentation
Every plot's roll station now has a server-updated countdown and progress bar for the scheduled 2x non-Common weight frenzy. During a server-only Frenzy override it displays the longer currently active scheduled/override duration; it does not predict future admin actions. Players also see a brief static banner when events become active, including simultaneous events, with a session-only accessibility option to hide it. Hiding the event tint remains independent. These are informational; roll odds and income are server-authoritative. Station updates run once per second and can lag during server stalls; verify Roblox visibility, accessibility, streaming and multiplayer performance.

### Reviewed duplicate cleanup
The backpack offers an optional server-reviewed sale of duplicate Standard unprotected loose parts, defaulting to Common as the maximum rarity. Groups match name, type, rarity, base income and recorded price; the first eligible inventory-order copy is retained and protected/non-Standard items are never sold or used as keepers. The fixed, paginated 60-second review lists each sold ID, kept ID and price. At confirmation the server rechecks every keeper, sale item and value, then atomically removes and credits the whole selection; stale, missing or newly protected items reject everything and new parts are excluded. This is an optional permanent sale, not a recommendation; extra parts may be useful for crafting. It relies on successful profile saves and still requires Roblox UI/multiplayer testing.

### Guided tutorial travel
The active six-step guide offers a one-tap travel shortcut to the current server-selected station or stand. If the only missing part types are protected, the guide instead opens the Protected Body Parts view. Destinations are re-derived from current server-owned tutorial and plot state, not accepted from a client position; travel still has a three-second cooldown, requires a living character and cancels a summit attempt. Completing steps and receiving the bonus still requires verified actions. Test streaming, collision, respawn and mobile layout in Roblox.

### Showcase hub directory
The hub has a refreshable public directory of its 15 booths, displaying only owner display names, ownership status and number of displayed creatures—not inventories or item IDs. Server-validated travel shortcuts lead to a booth or return portal; the existing nearby prompts remain necessary to inspect, claim or leave. Travel has a three-second session cooldown and requires a living character. Claimed booths display Roblox avatar thumbnails when available, with the existing nameplate as fallback. The snapshot can become stale. This remains showcase-only: no prices, transfers, purchasing or direct trading. Test Roblox thumbnails, mobile layout, collisions and simultaneous multiplayer use in a private published experience.

### Exact-offer and batch odds
New roll offers carry the server-calculated probability of their exact archetype, type and mutation at roll time, in addition to tier chance. The catalog has an informational calculator for a selected archetype, any or specific type and mutation, and one or more independent slots. It compares the current permanent slot count with a nine-offer token batch, using numerically stable at-least-one calculations. The inputs come from a manually refreshed server odds snapshot and can become stale; these are probabilities of offers, not guarantees or purchases. Rewards, gift crates and boxes have different distributions. Device rendering and live Roblox parity remain untested.

### Manual purchase review
Cash and free-part-voucher purchases now use a one-use server review of the exact offer, payment method and resulting mutation protection. A confirmation revalidates proximity, data health, offer details/expiry, storage, balance/vouchers and protection without yielding before consuming the offer. A changed or expired review spends nothing; auto-roll keeps its own separate rules. Old direct-purchase remote actions are rejected, so deploy the main client and server together and shut down old servers. Roll offers and their reviews remain temporary; successful ownership still depends on profile saving. Test device UX, timing and multiplayer in Roblox.

### Living-character proximity checks
Main-place and showcase-hub station/booth interactions now require a living Humanoid and a real HumanoidRootPart within 20 studs, in addition to their existing ownership, session-health and rate-limit checks. The checks block ordinary dead-character interactions but do not prove legitimate movement or prevent teleport exploits. Test normal character loading, death/respawn and custom rigs in Roblox.

### Reviewed buy-all
For two to nine current offers, an optional one-use server review shows every part, cash price, total and resulting protection before an all-or-nothing cash purchase. The server rechecks the exact offer order and attributes, expiry, auto-roll, protection setting, capacity and funds with no yield before moving any item; no vouchers are used. Any stale input rejects the whole batch. Individual reviewed cash/voucher purchases remain available. Test user experience, timeouts and concurrency in Roblox.

### Session gift farming safeguard
The nine timed rewards retain session timers and a per-session claim flag, but also save a per-gift UTC-day claim to limit rejoin/server-hop farming. The saved day cannot move backwards; a gift claimed in a session remains claimed in that session across midnight, and rejoining restarts its timer. Failed resource/capacity grants do not mark the daily claim. The limit and reward save together in the profile, but failed saves or crashes can lose both and allow retries; old claims cannot be reconstructed. This cap deliberately differs from unlimited per-session rewards in the original specification and requires balance testing. Update/publish both places together, back up data and shut down old servers before rollout.

### Main-place synchronization
Full state snapshots carry a session-only increasing revision; ticks advertise the most recent revision. A client that observes a gap requests a fresh full snapshot with a bounded retry, discards older revisioned snapshots/ticks, and shows SYNCING until caught up. Initial requests retry every two seconds; otherwise a quiet session refreshes after 30 seconds, with 15-second retries if no response arrives. There is no saved revision or client authority. This supplements reliable RemoteEvents and cannot recover an unsaved profile or guarantee a lossless sequence of cosmetic messages. The helper has standalone tests; actual network behavior and UI require Roblox testing.

### River crossing and foliage prototype
A continuous flat blue river surface connects to the western lake, away from plots and the treasure ring. Two simple wooden bridge decks cross the stream; their rails and water are non-colliding visual parts, so players can also walk straight across the water surface. Tree placement avoids the water and bridges; some trees use pale birch bark or layered pine-like canopies, with scattered non-colliding wildflowers. **TRAVEL → RIVER BRIDGE TRAIL** reaches the first crossing through the existing server-selected, cooldown-limited travel flow. These are placeholder shapes, not swimmable water or final art. Validate walking, respawns, map streaming, views, device performance and all nearby interactions in Roblox.

### Hand-picked parts sale
The backpack offers a separate hand-picked sale for up to 265 loose parts, with independent search, rarity/mutation filters, pagination, page selection and a selection retained across filters. Players can select mutations but not protected parts or creatures. The server returns a 60-second, one-use review of the exact selected IDs, attributes and sale values; confirmation rechecks every selection and either removes all and credits the total without yielding, or changes nothing. Other parts added after the review are excluded; pending IDs remain reserved. This does not replace the existing rarity bulk sale, individual sale or duplicate cleanup. Inventory and cash still depend on successful saves; actual mobile, latency, concurrency and Roblox UI testing is required.

### Assembly inventory safeguards
The assembly screen offers optional, session-only keep-one-loose-copy and Standard-only settings, initially off for compatibility. Both narrow auto-fill and apply to manual recipes; the server-owned review captures the chosen flags and rechecks them before committing. Keep-one requires a second loose part of the same exact name and type (a protected spare counts; creature components and offers do not, and mutations may differ). Standard-only rejects non-Standard labels and non-unit multipliers. With the switches off, selected last loose copies and mutated inputs still generate informational warnings based on the client snapshot. ### Optional touch haptics
Main-place players may opt into bounded local touch vibration through accessibility settings. The server labels their own successful roll batches (stronger for Mythic+ offers) and successful manual collections; automatic collection and other players' announcements do not trigger haptics. Touch motor support is checked with protected calls, Small falls back to Large, patterns are rate-limited to one every two seconds, and disabling cancels pending pulses and attempts to stop the motor. The setting is off by default and session-only. There is a test button; capability detection cannot guarantee physical vibration on every device. The standalone scheduler tests use mocks and actual Roblox devices, accessibility behavior and haptic APIs remain unverified.

### Profile status and requested checkpoints
Both places show a non-sensitive indicator when their DataStore lease contact is delayed (75 seconds) or Studio uses temporary memory data. The main place exposes a profile-status panel and a server-rate-limited manual checkpoint (one request per 60 seconds, at most one in flight). Checkpoints use the existing ordered snapshot and lease code, run asynchronously and report failure or successful/superseded completion only to that player. The reported age is time since the last successful load or save, not proof that subsequent changes have persisted. The existing 120-second health cutoff and best-effort final save remain unchanged. Failures, scheduler races, device UI and real DataStores need private Roblox testing; no lossless-save guarantee is made.

### Remote input boundary
Main and hub RemoteEvent handlers now apply per-session throttles before checking a bounded action/type envelope. The shared server validator rejects unknown actions, incorrect top-level types, non-finite numbers, unsupported value/key types, repeated or cyclic tables, excessive depth/entry counts and long strings. Its limits accommodate 365-item protection batches and existing 265-part sales. The existing gameplay, ownership, proximity and transaction checks remain authoritative. The two RemoteEvent entry points catch and rate-limit logs for unexpected handler errors; exceptions are not transactional rollback and prompts and background tasks are separate. This cannot prevent all exploit traffic, movement spoofing, race conditions or network costs. Tests cover maximum inputs and declared client actions with mocks; Roblox runtime and malicious multiplayer testing remain necessary.
