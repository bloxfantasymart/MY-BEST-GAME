# Testing the development build

These steps are for a **private test experience**, not your public game. The automatic checks in the README do not run Roblox Studio or prove that the game is safe to release.

## 1. Start the game

1. Follow the Rojo connection steps in the README. In Roblox Studio, use **View → Output** to see errors.
2. Click **Play**. Your character should appear near your plot. Check that the plot has a nameplate, three stations and 24 stands; the first 12 should be yellow and the rest gray.
3. Check the tutorial goal and station highlight. Walk to the red station and use its prompt. Pull the lever; check that a tray shows an offer. Buy it, or review and confirm skipping it. Try walking away and trying to roll: the server should reject the action.
4. Keep rolling and buying until you have a Head, Chest, Arms and Legs. Go to the purple pod. Select each part (or use auto-fill), then assemble. Verify the parts disappear and the creature appears in the backpack.
5. Use a yellow stand prompt and select the creature. It should appear, move gently and earn pending cash. Step on the green pad or tap the cash counter to collect. Check the displayed balance and level increase over time. Verify tutorial completion grants $1,000 once, stays complete after rejoining, and does not pay again.
6. Open **UPGRADES → PLOT THEMES** and select an unlocked theme; locked themes must not apply. Check the title above your avatar after respawning. Test inventory filtering, selling confirmation, paid leveling, travel and upgrades. Selling is permanent. Auto-roll requires rebirth 5 or the configured pass. Test it only after reading its warning: it spends cash. Move away from the station and check it stops.
7. Open **REWARDS → HOW TO PLAY**, check the two plaza leaderboards and the event countdown. The leaderboards cover the current server only. Use Studio's device emulator and a real mobile device to check that buttons and text remain usable.

Standalone tests do not run Roblox remotes, GUI, physics, scheduler or real DataStores.

### Tutorial guidance and recovery

Test respawn, streamed-out/streamed-in plot parts, distance, multiple players and mobile/PC layouts. The static marker is not a pathfinding arrow, and standalone tests cannot verify actual Roblox rendering or networking.

### Persistence ordering and malformed profiles

Use a separate private published test experience with Studio API access enabled only for that experience. Simulate failed writes, a lost lease, timeouts and shutdowns; these guards cannot guarantee a successful final save.

Inject malformed data only into disposable test keys: sparse/dictionary-shaped part and creature inventories, empty IDs and invalid lease fields must fail to load and leave the stored profile untouched. ### Item ID and roll failure safety

Run `python3 tests/run_item_ids_tests.py /path/to/luau`. The allocator retries at most five times against IDs in the current player session, including stale saved-layout references and active reviews. Roll batches are prepared before replacing offers or recording progression; errors leave the inventory and offers unchanged. Box creation failure does not consume the box. ### Interaction rate limits

Run `python3 tests/run_interaction_gate_tests.py /path/to/luau`. The main place and showcase hub use separate per-player remote and physical-prompt limits. In a private Roblox test, try normal prompts, rapid repeated prompts and multiple players; these controls do not constitute complete exploit or denial-of-service protection.

### Reconnect and local session exclusion

The shutdown and persistence mock suites cover a reconnect during an in-flight join or departure, concurrent loads in one server, a final-save overlap, and a rejected final snapshot. An invalid or uncopyable final snapshot is not saved, and its persistent lease can remain until expiry, so recent progress can be lost. The tests simulate DataStore behavior and do not prove real cross-server safety: verify fast reconnects, failed saves and server shutdown in a private published experience.
